# 今日剩余计划动态调整

在管家聊天中发送“更新今天的计划”“重新排今天剩下时间”或“我今天临时有事，帮我调整”。管家读取北京时间、当日任务和课程、有效长期记忆及目标，返回 `today_revision`。点击 **应用到今天** 才提交。普通聊天和明日计划流程不变。

## 上线步骤

1. Supabase Dashboard 选择现有项目 `wtofvklcjtybapxjqxpu`，打开 SQL Editor。
2. 确认已经执行 001–004。在新查询中粘贴并运行 `supabase/migrations/005_today_replanning.sql` 的完整内容。005 是一次性迁移；不要重复执行，也不要修改或重跑 001–004。
3. 在最新 main 仓库目录部署聊天函数：

   ```sh
   npx supabase@latest functions deploy butler-chat --project-ref wtofvklcjtybapxjqxpu --use-api
   ```

4. 保持 `supabase/config.toml` 中现有 `verify_jwt = false`。函数内部通过 `auth.getUser(jwt)` 验证真实登录用户，所有数据库读写使用此用户的 JWT 和 RLS。不创建项目、不修改 Secrets、不需要 service role key。
5. 等待 Vercel 的 main 部署完成，登录网站，从首页创建/读取今天的计划，再去管家发送调整请求。先确认任务未改变，再点击“应用到今天”。刷新首页检查时段，点击“查看调整记录”检查原因和前后快照。

未执行 005 时，新版聊天函数对今日调整返回明确的迁移提示；普通聊天及明日流程继续可用。`generate-tomorrow-plan` 本次无需重新部署（只有共享错误文案新增，原行为未变）。迁移、函数部署和线上真实 AI 验收不是本地自动测试的一部分。

## 保护与冲突处理

- `tasks` 新增可空的 `scheduled_start` / `scheduled_end`。旧任务没有时段，不会被猜测成过去任务，可参与重排。
- 已完成任务、已开始任务和已过时段任务不参与修改。RPC 不改它们的标题、状态、时段或更新时间，也不改当日主目标。
- 今天最多 6 项剩余安排，可以为 0 项。每项包含具体起止时间、预计分钟数、原因和完成标准。返回列表是对可调整任务的完整替换；原任务 ID 被引用时保留 ID，撤下的任务保留在修订前快照中。
- `get_today_replanning_snapshot()` 只读取当前用户的当日计划/任务/课程/反馈和当前有效目标/记忆。快照保存在助手消息元数据中，由服务端读取数据库生成，不接受模型生成的快照。
- `apply_today_revision(p_message_id)` 是 security invoker 原子 RPC；确认时重新读取上下文并比较完整快照。任务完成、增删、修改，以及课表、有效记忆、目标或当日反馈变化都会使旧预览失效。
- 用户级事务锁覆盖上述表的 INSERT / UPDATE / DELETE（包括插入新行），避免检查到保存之间其他设备插入或更改任务/约束。行锁进一步保护本次修改；失败整笔回滚。
- RPC 再次检查时间、任务来源、唯一标题、重复 ID、时段重叠、课程和明确长期时间块。预览 30 分钟过期，跨日或开始时间已到也会拒绝。重复调用同一消息 ID 返回原结果，不重复添加任务；网络断开后可安全重试。
- `today_plan_revisions` 开启并强制 RLS，四种操作仅允许 `auth.uid() = user_id`。每次成功应用保存原因、生成时间、应用时间和前后完整任务快照。首页及历史页可读取最近 50 次记录。

## 课程与长期规则的范围

课程优先采用课表已保存的节次时间；未保存设置时使用仓库内既有的 1–12 节默认作息。第 13/14 节或明确配置中缺少钟点时，要求先补齐，不猜测空闲。

有效记忆中形如 `23:00–07:00`、`18:00 到 21:00` 的明确时间范围会作为固定占用进行服务端校验（跨午夜拆成两个时间块）。目前这些时间块按每日规则处理；带复杂工作日条件的自然语言规则由 AI 理解，建议先确认明确的当日适用时间。仅有“健身至少 3 小时，含通勤”等自然语言时长规则会参与 AI 规划，但没有确定钟点可做数据库时段校验。预览仍需用户确认；系统不会虚构作息时间。
